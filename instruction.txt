This file explains EVERYTHING that lives in the code so you can
change anything in the future without breaking the site.

---------------------------------------------------------------
 1. WHAT THE SITE IS BUILT WITH
---------------------------------------------------------------
- Plain HTML + CSS + JavaScript. No build step, no framework.
- One shared stylesheet  -> styles.css   (design system for ALL pages)
- One shared script      -> main.js       (nav, animations, marquee, year)
- Each HTML page has a tiny <style> block for page-specific CSS.
- Everything is responsive (mobile-first) — written for phones first,
  then enhanced at larger widths.

 3. COLORS, FONTS, SPACING  (styles.css → "Design tokens")
---------------------------------------------------------------
Open styles.css and look at the :root block near the top. These are
the ONLY place to change the look of the whole site:

    --ink           main text / dark surfaces   (#0e0e0e)
    --paper         main background             (#f5f2ed)
    --paper-warm    secondary background        (#ede9e0)
    --accent        brand/orange                (#a83310 — AA-safe: ≥4.5:1)
    --accent-light  light orange tint           (#f0d5c8)
    --muted         secondary text              (#7a7469)
    --border        hairlines / borders         (rgba 12%)

  HOW TO: change the brand color
     1. Edit --accent (and --accent-light if needed).
     2. Done — every button, tag, underline, and heading accent updates.

  HOW TO: change fonts
     Edit --serif (headings, uses Instrument Serif) and/or
     --sans (body, uses DM Sans). Font files are loaded from Google
     Fonts in the <head> of every HTML page.

  HOW TO: change spacing globally
     --space-* tokens define the spacing scale.
     The "--gutter" value controls side padding (16px mobile → 48px desktop).
     The "section" padding rules control vertical space between sections
     (see item 4).

---------------------------------------------------------------
 4. LAYOUT & RESPONSIVE RULES  (styles.css)
---------------------------------------------------------------
- Content is capped at 1440px wide, centered on very wide screens
  (`--max-w`).
- Breakpoints used everywhere (mobile-first, min-width):
    +480px  → tablets narrow
    +768px  → tablets / small laptops
    +1024px → laptops / desktop
    +1280px → wide desktop
- Sections: `section { padding-block: clamp(3.5rem, 8vw, 6rem) }`
  means "no less than 3.5rem, no more than 6rem, scales with screen".
  HOW TO: tighten section spacing site-wide → lower the numbers here.
  HOW TO: tighten ONE page → override in that page's <style> block
          (about.html does this with `padding-block: clamp(2rem,5vw,3.5rem)`).
- Nav height is fluid: --nav-height = 64px → 80px across breakpoints.
  Never hardcode pixel nav heights in page CSS — use var(--nav-height).

---------------------------------------------------------------
 5. NAVIGATION  (in every HTML file + styles.css)
---------------------------------------------------------------
- The same <nav class="nav"> markup is copied in every page.
  Make sure every page gets the SAME nav if you add a link.
- Active page is marked automatically by main.js (adds .active).
  It animates: accent bar (mobile) / underline (desktop).
  HOW TO: add a new page to the menu
     1. Create the page (copy an existing one).
     2. Paste the same nav markup, add your <li><a href="yourpage.html">…</a>.
     3. The active underline works automatically.

---------------------------------------------------------------
 6. PAGES & SECTIONS — the rules every page follows
---------------------------------------------------------------
- Every <style> block is organized into labeled sections like:
      /* PROFILE SPLIT (mobile-first) */
      /* STATS ROW (mobile-first) */
  Keep this style when you add code — labels = easy maintenance.
- Every content block in the <body> has an HTML comment above it:
      <!-- HERO -->, <!-- AT A GLANCE -->, ...
- Sections use aria-label / aria-labelledby for accessibility.
  HOW TO: add a new section to a page
     1. Add <section id="your-id" aria-labelledby="your-title">.
     2. Inside: <div class="section-label">Kicker</div> and
        <h2 class="section-title" id="your-title">Heading</h2>.
     3. Add your content. CSS comes free from styles.css.
     4. Write the rules in that page's <style> block (or styles.css
        if the section repeats on several pages).

 9. MARQUEE STRIP  (index.html)
---------------------------------------------------------------
The scrolling "Business Analysis ✦ Technical Writing ✦ …" strip.
  HOW TO: add/reorder skills → edit the <span> items inside
          <div class="marquee-inner"> (repeat the set once for the loop).
JS in main.js auto-duplicates content so the loop never shows a gap.
It stops when the visitor prefers reduced motion (WCAG 2.2.2).
Do NOT re-enable it with !important — index.html documents this.

 12. CASE STUDIES  (project-*.html)
---------------------------------------------------------------
Shared layout from styles.css ("Case study" section):
    .case-studies-header   hero of the case
    .case-layout           facts sidebar (sticky on desktop) + body
    .case-facts            quick facts box
    .case-section          numbered content blocks (h2 with .num)
    .case-cta              bottom "let's work together" banner

  Reading rhythm (shared, DO NOT override per page):
    Body text in .case-section is capped at 68ch with margin-bottom
    1.25rem (headings, paragraphs, lists all use the same gap). The
    section gap (2.5-3.5rem) separates chapters. All case pages inherit
    this — no <style> block needed in project-*.html at all.

  HOW TO: add a new case study page
     Copy project-talentvis-accounting.html as the template (it is the
     cleanest model): same head, nav, case-* markup, and NO <style>.
     Fill hero, quick facts, and the numbered case sections. Keep every
     block as <section class="case-section fade-up"> with an h2 + .num.
     Never add page-level CSS — spacing lives in styles.css.
Some sections show a [TBD] placeholder until real content is added.
  HOW TO: fill a [TBD]
     Look for <span class="case-tbd">…</span> in project-*.html and
     replace the placeholder with real text. Keep the same structure.

 13. CONTACT FORM  (contact.html)
---------------------------------------------------------------
Uses Web3Forms — no backend needed. The access key lives in the form
hidden input at the top of <form>:
    <input type="hidden" name="access_key" value="d513c5ba-fbe5-4549-bf53-a7445c9bb7f2">
  HOW TO: use a different inbox
     1. Change the "from" email / recipient in the form fields
        (subject, from_name, and the key above).
     2. First live test: visit https://web3forms.com → send a test
        message to confirm your email is approved.
Messages arrive in your email. Client-side validation is in the
<script> at the bottom of contact.html (also does aria-invalid + focus
management for accessibility).

  IMPORTANT — spam protection (do not skip): the access_key is public by
  design (it's in the HTML). Visit https://web3forms.com → your form →
  enable (a) domain restrictions to your GitHub Pages URL and
  (b) "Google reCAPTCHA" (v3, invisible) or the built-in spam check.
  The honeypot (botcheck) field is already present in the form.

---------------------------------------------------------------
 19. GOLDEN RULES (follow these when editing)
---------------------------------------------------------------
1. Mobile first: write styles for small screens, then add
   @media (min-width: …) to improve larger screens.
2. Small screens never get horizontal scroll — if it appears, fix
   the layout, don't add overflow-x:hidden.
3. Put shared styling in styles.css; page-only styling stays in the
   page's <style> block.
4. Label every CSS block and HTML section you add.
5. Use existing classes/buttons instead of creating new ones.
6. Keep touch targets ≥ 44px for buttons.
7. Don't hardcode nav height — use var(--nav-height).
8. Test at least 320px and 1024px before deploying.
9. Accessibility is built-in — don't remove: the skip-to-content link
   (first element of <body>), the <main id="main"> landmark, aria-invalid
   on form fields, focus management, or the reduced-motion rules.
10. All pages are wired for keyboard only: nav closes on Escape and
    returns focus to the toggle.
